Data safety

先保证不丢，再谈功能。

Markdown Writing 把本地文件视为唯一事实来源。保存、退出保护和恢复都围绕这条原则设计。

安全设计 设计原则 保存流程 删除与恢复 退出与恢复 能力边界

设计原则

编辑器的第一责任不是让界面显得智能，而是在异常和误操作发生时，尽量不让用户失去已经写下的内容。

  • 本地优先：普通 Markdown 文件保留在磁盘，应用不会把文档锁进私有格式。
  • 恢复优先于报错：异常退出和误删除都尽量提供可执行的恢复路径。

一次保存经历什么

自动保存和手动保存共用同一条提交路径，不会出现两种保存方式背后行为不一致的问题。

01
写入临时文件

新内容先写到目标目录中的临时文件，避免原文件在写入中被截断。

02
原子替换原文件

内容完整写入后替换原文件，再做必要的清理。

03
清理恢复状态

保存成功后清理已经落盘的恢复内容。

保存失败不回滚编辑状态

页面继续保持 dirty 状态，恢复快照也会保留。用户可以重试、另存或先复制内容。

删除与恢复

删除文档时文件会先移动到应用数据目录而不是立即抹除，但应用内暂不提供恢复入口；磁盘文件消失时仍可保留编辑内容并另存副本。

场景 保护动作 应用内入口
误删除文档 文件先移动到应用数据目录 暂不提供
外部文件消失 保留编辑内容 另存副本

退出与崩溃恢复

存在未保存内容时，退出流程会先尝试完成保存，并列出仍未落盘的文档。正常关闭后清理恢复状态，异常退出则保留下一次启动可读取的快照。

恢复快照包含文档、内容和编辑模型版本。启动时若发现未处理快照，会询问恢复还是丢弃。

能力边界

这些机制主要防止正常使用中的误操作和进程中断，不能替代系统备份或磁盘加密。

  • 应用不会把文档上传到云端，网络只用于读取 GitHub Releases 等明确功能。
  • 应用数据目录保存被删除文件的副本与元数据，应纳入系统备份。
  • 如果磁盘损坏、权限被拒绝或系统工具直接改写文件，应用会尽量保留恢复副本，但无法保证物理介质本身可恢复。
  • 涉及敏感内容时，应配合加密磁盘、文件权限和可信备份策略使用。
